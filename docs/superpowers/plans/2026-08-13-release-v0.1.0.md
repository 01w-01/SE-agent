# FBW v0.1.0 课程交付发布 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在明确保留 WebUI 课程偏离和学生反思边界的前提下，通过现有 GitHub Actions 发布可验证的 Windows x64 纯 CLI `v0.1.0`，并完成双端证据收口。

**Architecture:** 发布准备 PR 只收紧 workflow Release 说明和文档裁决；合并后由不可移动的 `v0.1.0` annotated tag 触发测试、历史扫描、PyInstaller 构建和 GitHub Release。下载发布附件做独立复核后，再以证据 PR 记录 Release URL、run、SHA 与限制，最后同步 NJU 并清理隔离工作区。

**Tech Stack:** PowerShell 7、Python 3.13、uv、pytest、Ruff、PyInstaller、GitHub Actions、GitHub Release、Git/NJU GitLab。

## Global Constraints

- 发行版本固定为 `v0.1.0`，Python 包版本保持 `0.1.0`。
- 只发布 Windows x64 纯 CLI：`fbw-harness.exe` 与 `fbw-harness.exe.sha256`。
- 不实现或暗示存在 WebUI、终端 REPL、macOS/Linux 发行物或 Authenticode 签名。
- “纯 CLI 软件可发布”不得改写为“课程清单 100% 合规”；WebUI 继续作为有意偏离。
- `REFLECTION.md` 正文必须由学生本人撰写，本计划不创建或代写正文。
- 任何秘密扫描、测试、构建、EXE 冒烟或 SHA 复核失败都阻止成功声明。
- Release 中不得包含 Key、环境文件、日志、记忆或真实 API 请求/响应。
- 不重写或强制移动公开 tag；失败后使用新提交与新的 patch 版本恢复。
- 三份 `docs/STATUS.md`、`docs/LOG.md`、`docs/PROGRESS.ascii.md` 始终留在根仓库且不得提交。

## File Structure

- `.github/workflows/release.yml`：tag 后测试、扫描、构建、冒烟和 Release；补齐面向用户的限制与凭据说明。
- `mini-harness/tests/test_distribution_files.py`：静态锁定 Release workflow 的附件、说明和安全边界。
- `README.md`：公开获取、SHA、凭据配置、平台限制和实际 Release 链接。
- `PLAN.md`：记录用户对 WebUI 偏离、发布裁决变化及完成 commit/PR/tag。
- `AGENT_LOG.md`：记录技能、人工决定、测试证据、Release workflow 与双端同步。
- `docs/evidence/release-checklist.md`：区分软件发布状态、课程偏离与非阻断限制。
- `docs/evidence/release-v0.1.0.md`：发布后新增的 tag、commit、run、附件和下载复核证据。
